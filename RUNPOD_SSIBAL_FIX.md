# Обновление SSIBAL Animate

Этот пакет меняет код worker, а не файлы моделей. Повторно скачивать модели в Global Volume не требуется.

## Что исправлено

- Вместо TSVideoCombineNoMetadata используется стандартная VHS_VideoCombine. Сохранены обработка цвета TSColorMatch, Uni3C, исходное аудио, пять LoRA и их силы.
- LoRA загружаются целиком в RAM до сэмплинга. При переносе их на GPU больше не требуется лениво читать отображённые файлы с Global Volume. Это расходует RAM; ускорение нужно измерить на реальном worker.
- Worker слушает события ComfyUI, показывает текущую ноду и шаги сэмплинга. Готовность определяется по завершённой истории или событию `executed` именно финальной ноды видео. Файл на диске, превью и незавершённая пакетная запись не считаются готовым результатом.
- В пакет также входят подготовленные ранее исправления ONNX Runtime для CUDA 12.8 и настройки загрузки моделей с Global Volume.

Гипотеза о необходимости отмены в RunningHub не подтверждена: в API export нет явной ноды отмены, а предоставленный лог остановился до сэмплинга. Старый worker выключен, проверить его выходные файлы уже нельзя. Изменения проверены без GPU; успешная генерация SSIBAL новым образом пока не подтверждена.

## Как применить

1. Распакуйте `OFM_Runpod_Serverless_GitHub.zip`. Замените файлы в вашем GitHub репозитории `sypex6/ofm-studio-runpod` содержимым архива, сохраняя пути. В корне репозитория должны находиться `.github`, `studio`, `tests` и инструкции. Не загружайте сам ZIP вместо исходников. Токен HF и ключи API в архив не включены.
2. Сделайте commit в `main`. В Actions дождитесь зелёного результата **Build Runpod Serverless image**. На странице сборки, в Summary, скопируйте имя образа с тегом нового commit: `ghcr.io/sypex6/ofm-studio-runpod:<полный SHA commit>`.
3. В настройках текущего Runpod Serverless endpoint замените Container Image на это имя с новым тегом. Не используйте старый тег: уже запущенные контейнеры не обновляются от замены файлов на VPS.
4. Сохраните подключённый Global Volume с моделями и настройки `STUDIO_HOST`. Для Global Volume задайте `MODEL_STORAGE=global`, `DOWNLOAD_MODELS=0`. Для первого теста можно выбрать `WORKFLOW_PROFILES=animate-wrapper`; если включены оба workflow, оставьте `animate-ki,animate-wrapper`.
5. Проверьте старые задачи в Studio: отмените зависшие и ненужные запросы, включая очередь. Запустите одну новую короткую задачу SSIBAL с готовым изображением, длительностью 2–3 секунды, размером 480×832 и 4 шагами. Подготовка фото для такого теста не требуется. Генерация платная.
6. В логах нового worker должны появиться `WAN: eager LoRA reads enabled`, `Studio: LoRA RAM read complete`, затем `ComfyUI: node 273 WanVideoSampler`, шаги сэмплинга, финальная `VHS_VideoCombine` и `Saving result to Studio`.

Если снова возникнет долгая задержка, пришлите строку текущей ноды из логов вместе с `nvidia-smi` и загрузкой CPU. Необходимость изменения алгоритма SSIBAL, а не загрузки/сохранения, можно оценить по этим данным.
